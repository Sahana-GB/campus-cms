\section{Automated Testing and Verification}
\label{sec:testing}

\subsection{Testing Philosophy and Strategy}
To prevent regressions across collaborative features and guarantee data integrity, the project implements a rigorous dual-layer automated testing strategy combining Java JUnit 5 tests and Python standard library unit tests.

Testing guidelines strictly enforce:
\begin{enumerate}
    \item \textbf{Hermetic Test Isolation:} Database tests operate against temporary or in-memory SQLite instances created from \texttt{db/schema.sql}, preventing test side-effects from polluting \texttt{data/campus.db}.
    \item \textbf{Role-Based Security Verification:} Every dashboard and protected service method is tested against valid and invalid session roles to verify that unauthorized access throws expected security exceptions.
    \item \textbf{Edge Case Coverage:} Validation includes duplicate entity detection, constraint boundary values (e.g., negative course credits, year out-of-range), and transaction rollback on insertion failure.
\end{enumerate}

\subsection{Java Test Suite (JUnit 5)}
The Java test suite comprises \textbf{136 automated test cases} across all architectural tiers:
\begin{itemize}
    \item \textbf{Authentication and Session (\texttt{com.campus.cms.auth}):} Validates password hashing and verification in \texttt{PasswordUtilTest}, role permission checks in \texttt{AuthServiceTest}, user queries in \texttt{UserDAOTest}, profile password modifications in \texttt{ProfilePanelTest}, and login window state transitions in \texttt{LoginFrameTest}.
    \item \textbf{Student Management (\texttt{com.campus.cms.students}):} Tests CRUD lifecycle, roll number uniqueness, email constraints, and active/inactive state transitions in \texttt{StudentDAOTest} and \texttt{StudentsPanelTest}.
    \item \textbf{Course Catalog and Faculty (\texttt{com.campus.cms.catalog}):} Validates active slot conflict detection, course capacity enforcement, and faculty assignment in \texttt{CatalogDAOTest}.
    \item \textbf{Enrollment and Reports (\texttt{com.campus.cms.enrollment}):} Covers course request approval/rejection workflows, CGPA-based automatic seat allocation, drop mechanics, CSV report generation, and enrollment period toggle states in \texttt{EnrollmentServiceTest}, \texttt{EnrollmentPeriodAndReportsTest}, and \texttt{CsvExporterTest}.
    \item \textbf{Grading and Assessment (\texttt{com.campus.cms.grading}):} Validates assignment creation, enrolled student auto-population in the grading table, draft score persistence, and grade publication in \texttt{GradesPanelTest}.
    \item \textbf{Dashboards and Core UI (\texttt{com.campus.cms.dashboard}, \texttt{com.campus.cms.core}):} Verifies proper component initialization, greeting derivation, action bar wrapping, and card switching in \texttt{AdminDashboardTest}, \texttt{FacultyDashboardTest}, \texttt{StudentDashboardTest}, and \texttt{DashboardCardTest}.
\end{itemize}

All 136 tests execute via Maven and pass with zero failures:
\begin{verbatim}
mvn test
Results: Tests run: 136, Failures: 0, Errors: 0, Skipped: 0
\end{verbatim}

\subsection{Python Test Suite (unittest)}
The synthetic student data generator is verified by 11 comprehensive automated tests in \texttt{python/test\_generate\_data.py}:
\begin{itemize}
    \item Validation of cohort generation across sizes: 100, 1{,}000, and 10{,}000 records.
    \item Exact Java PBKDF2-HMAC-SHA256 password hash vector verification.
    \item Uniqueness guarantees for generated usernames, roll numbers, and emails.
    \item Foreign key referential integrity via SQLite \texttt{PRAGMA foreign\_key\_check}.
    \item Database structure integrity via SQLite \texttt{PRAGMA integrity\_check}.
    \item Atomic rollback verification upon injected insertion failures.
    \item Idempotency and dry-run execution checks.
\end{itemize}

The Python suite executes cleanly:
\begin{verbatim}
python -m unittest python/test_generate_data.py
Ran 11 tests in 49.146s -- OK
\end{verbatim}
